# AI labour experiment operations

The prior deterministic candidate and evidence remain unchanged. The AI continuation is additive in the isolated candidate worktree. Nothing authorises a production release or general workforce onboarding.

## Reproduce the bounded experiment

Run from the candidate repository on the already provisioned Linux qualification host:

```sh
npm ci
npx tsx scripts/qualify-labour-ai.ts /absolute/path/to/a-new-evidence-directory
```

The script deliberately requires a fresh evidence directory. The native runtime and three model paths are explicit in the qualification script; they must already exist. No model download, provider credential, network inference or protected service restart is performed. This qualification implementation is Linux-only and uses the existing owned-process lifecycle plus GNU time. Model output cannot choose executable names, paths or shell arguments. Generated coding answers are scored as bounded patch expressions, not executed as arbitrary code.

`LABOUR_WAIT=1` pauses after calibration until a `RUN` file exists, then retains the loopback dashboard until `STOP` exists. `LABOUR_PORT` selects the isolated dashboard port. The script's literal operator token is a local qualification fixture, not a production credential; never expose this harness publicly. A same-host headless browser may authenticate through the normal operator form and use existing Video Evidence Mode. No SSH forwarding policy change is required.

CPU metering uses XCU: one unit represents one measured child user+system CPU millisecond. It includes cold model load, inference and child shutdown. GNU time has 10 ms reporting resolution. The parent verifier uses measured process CPU rounded up to a millisecond. Native sum-tool execution is timed separately; parent/controller overhead, memory bandwidth, energy and host opportunity cost have no defensible monetary conversion in this experiment. Local compute is not treated as free. The accounting ceiling is an internal liability ceiling, not an OS cgroup quota or financial invoice.

Quotes use prior same-worker, same-backend-revision, same-job measurements. Maximum reservation remains separate from the estimate. Unknown CPU measurement uses a conservative internal ceiling and explicit UNKNOWN flag; it is not a measured zero. Actual measured resources are retained even where internal charges are capped. There is no currency saving or real financial settlement.

All strategies share frozen calibration and exact verifier criteria. Held-out history is isolated by strategy inside one journal, so an earlier strategy cannot teach the next one its held-out results. The case order is fixed and strategy execution order rotates by case. This is a small, sequential experiment; host-load noise and cold-start behaviour limit generalisation.

Natural failures remain part of each strategy's economics. Subsequent controlled process interruption, backend-identity change, quarantine and containment controls are separately labelled and excluded from those totals. Qualification failures deny the corresponding capability; manually making a worker available never overrides its failed qualification. No automatic backend escalation or permission widening is implemented.

An interrupted qualification journal is preserved with its lock. Do not remove the lock to replay uncertain work. Use a new evidence directory. Production reconciliation, multi-writer storage, distributed settlement, open-ended agent tasks and broad tenant security need separate implementation and qualification.
