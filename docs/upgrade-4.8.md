# Upgrade Agent Control 4.7.1 to 4.8.0

1. Record the running version, launch method, configuration location, state location, and current health. Stop only the intended installation through its established procedure.
2. Preserve a consistent backup of configuration and state. Keep credential files private and outside source archives.
3. Clone `v4.8.0` into a clean sibling directory. Do not pull over a dirty installation.
4. Run the documented bootstrap with the supported Node.js runtime, then point the new installation at the preserved configuration and state.
5. Start on loopback with the existing operator authentication. Verify version, Estate Topology, an ordinary Node Dashboard, retained history, and a harmless governed observation before changing any operational exposure.
6. Where authoritative nested relationships exist, verify progressive disclosure, execution-environment detail, runtime state, route explanation, resource scope, Run Inspector, and evidence download.
7. Keep the 4.7.1 checkout and backup unchanged until acceptance completes.

The 4.8 schema changes are additive. Existing resources without typed containment remain ordinary devices and do not acquire empty nested panels. Legacy containment attributes remain readable. No mandatory state or configuration migration is required.

Runtime executable detection does not grant execution qualification. Do not enable a runtime, transport, worker, or capability merely because it appears in discovery.

For rollback, stop 4.8, preserve its new logs and evidence, and restart the saved 4.7.1 checkout against the pre-upgrade backup. Do not run both versions against the same writable state or overwrite either history.

Release publication does not deploy or modify an operational Agent Control installation.
